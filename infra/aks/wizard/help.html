Wizard Option Help

Use this reference to understand current wizard fields, presets, validation rules, and generated outputs.

Step 1: Core

Subscription ID
Azure subscription where deployment runs.
Location
Region for deployment metadata and regional resources.
Mode
automaticManaged for simpler defaults, automaticPrivate for private AKS Automatic, standardPrivate for private Standard AKS with BYO networking.
Stage
Choose how far the script runs: Preflight, Plan, Deploy, Smoke, or All.
Workload Name / Environment Name
Naming inputs used to derive resource name defaults.
AutoName
Generates names automatically to reduce manual naming work.
Interactive
Prompts for inputs during execution instead of non-interactive run.
Resume
Continues from a prior interrupted deployment state.
SkipWhatIf
Skips the what-if planning phase for faster deployment.
Presets
Four presets can pre-fill the wizard: Minimum Cost, Private Enterprise, BYO Everything, and Standard Private CNI.
Minimum Cost preset
Sets automaticManaged, disables LAW/AMW/Grafana, uses acrMode=none, turns off Bastion and Jumpbox, sets hub mode to none, and clears BYO IDs and manual overrides.
Private Enterprise preset
Sets automaticPrivate with hub mode peering, enables LAW/AMW/Grafana, sets acrMode=existing with enterprise ACR placeholder, enables Bastion and Jumpbox, and pre-fills a cluster admin group override example.
BYO Everything preset
Sets automaticPrivate with hub mode peering, disables LAW/AMW/Grafana, sets acrMode=existing, fills sample BYO spoke/hub subnet and DNS IDs, disables Bastion and Jumpbox, and sets VNet integration plus overlay networking values.
Standard Private CNI preset
Sets standardPrivate with hub mode peering, enables LAW/AMW, disables Grafana, uses acrMode=none, enables Bastion and Jumpbox, and sets API access to privateEndpoint with flat CNI (enableOverlay=false).
Step Validation
Step navigation blocks forward movement if required fields for the current step are missing.

Step 2: Features and ACR

Container Insights (LAW)
Enables/creates Log Analytics workspace usage for AKS monitoring.
Azure Monitor Workspace
Enables Azure Monitor workspace integration.
Managed Grafana
Enables Azure Managed Grafana for dashboards.
ACR Mode: none
No container registry integration changes.
ACR Mode: new
Creates a new ACR; requires acrName.
ACR Mode: existing
Uses one or more existing ACR resource IDs.
Existing ACR IDs
One full resource ID per line when ACR mode=existing.
Validation
ACR mode=new requires ACR name; ACR mode=existing requires at least one ACR resource ID.

Step 3: Network and BYO

API Server Access Mode
vnetIntegration places the API server NIC in a delegated /28 subnet (no management PE path). privateEndpoint uses a traditional private endpoint path. This selector is shown only in standardPrivate mode.
Network Mode
Overlay + Cilium gives pods virtual IPs; Flat Azure CNI gives pods routable VNet IPs. This selector is shown only in standardPrivate mode.
BYO Node Subnet ID
Existing subnet where AKS worker node VM NICs are placed. Skips VNet module creation.
Use BYO checkboxes
Network BYO fields are opt-in. If a checkbox is off, that BYO override is omitted and template defaults are used.
Create node subnet if missing
When enabled, generated deploy.ps1/deploy.sh commands can check whether the BYO node subnet exists and create it if missing.
Node Subnet CIDR
Address range used only when create-if-missing is enabled and the BYO node subnet does not already exist (example: 10.240.0.0/22).
BYO Pod Subnet ID
Optional dedicated subnet for pod IPs (used with flat Azure CNI or dual-subnet overlay).
If BYO Pod Subnet ID is left blank
No byoPodSubnetId override is passed. Deployment falls back to template defaults for the selected mode/network configuration instead of forcing a dedicated BYO pod subnet.
BYO API Server Subnet ID
Existing /28 subnet delegated to Microsoft.ContainerService/managedClusters for VNet integration.
BYO Private DNS Zone ID
Existing private DNS zone for private API server name resolution.
If other BYO IDs are left blank
Blank BYO fields are simply omitted from overrides. The deployment then uses built-in template behavior for creating or selecting resources based on your mode and other provided values.
Hub Connectivity Mode
Controls how the AKS/spoke side is connected to the hub side.
none
No hub connectivity resources are configured. Use for standalone or lowest-cost setups with no hub access path.
peering
Uses VNet peering between spoke and hub. This is the default private-enterprise pattern when you want full routed connectivity between networks.
privateEndpoint
Uses a private endpoint-based hub access path (for scenarios where endpoint-style access is preferred over full network peering).
both
Attempts to configure both peering and private endpoint paths. Useful when you need both routed network connectivity and endpoint-based access patterns.
BYO Hub VNet ID
Existing hub VNet to connect with spoke/AKS resources.
BYO Hub Bastion/Jumpbox/PE Subnet IDs
Specific existing subnets in hub VNet used by Bastion, jumpbox, and private endpoint.
Validation
If BYO node subnet is set for private modes and VNet integration applies, BYO API server subnet is required. BYO hub + Bastion/Jumpbox deployment also requires matching hub subnet IDs.
Deploy path note
Create-if-missing subnet behavior is implemented in script flows (deploy.ps1 and deploy.sh). Direct az deployment and Terraform snippets do not auto-create missing BYO subnets.

Step 4: Access and Overrides

Bastion SKU
SKU for Azure Bastion deployment (for SSH/RDP access patterns).
Jumpbox SSH Key Path
Private key path used for jumpbox SSH-related command generation.
Deploy Bastion
Controls whether Bastion resources are deployed.
Deploy Jumpbox
Controls whether the Linux jumpbox VM is deployed.
Raw hashtable body (manualOverrides)
Advanced append-only PowerShell override entries not directly exposed in the UI.

Step 5: Review and Generate

Generate
Builds validation output, computed override hashtable, and command blocks.
Copy deploy.ps1
Copies the generated PowerShell deployment command.
Copy az command
Copies direct az deployment sub create examples for PowerShell and Bash.
Copy terraform
Copies a Terraform tfvars block plus plan/apply command sequence.
Validation Panel
Shows blocking errors and warnings. Status pill indicates Ready, Ready (Warnings), or Validation Errors.

Behavior Notes

State Persistence
Form values, selected preset, and current step are saved in browser local storage and restored on reload.
Standard-only Controls
API server access and network mode controls are hidden outside standardPrivate.
Private Mode Guardrails
Warnings are shown for combinations that are valid but partially ignored by deployment logic (for example, PE paths while using VNet integration).
